================================================================
OBSERVAÇÕES SOBRE O ARQUIVO Comandos.txt ORIGINAL
================================================================
Ao rodar o arquivo do jeito que estava, dois problemas apareceram
e precisaram ser corrigidos para o script funcionar:

1) A tabela CLIENTE foi criada com a coluna DATA_NASC, mas os
   INSERTs usavam o nome DT_NASC. Corrigido para DATA_NASC.

2) Dois INSERTs em VENDA_ITENS repetiam a mesma chave primária
   (PRODUTO_ID, VENDA_ID) já usada em linhas anteriores:
   - "VALUES(2,1,...)" para a venda 2 deveria ser VENDA_ID=2, não 1
     (o valor da venda 2 é 500.00, batendo com esse item).
   - "VALUES(1,1,...)" para a venda 5 deveria ser VENDA_ID=5, não 1
     (o valor da venda 5 é 1000.00, batendo com esse item).
   Sem essa correção, o INSERT dava erro de chave primária duplicada.

3) O DELETE de exemplo ("DELETE FROM CIDADE WHERE ID = 1") foi
   executado propositalmente sem alteração. Ele FALHA com erro de
   violação de chave estrangeira, porque a cliente HELENA tem
   CIDADE_ID = 1. Isso é o comportamento correto de um banco com
   integridade referencial: não deixa apagar uma cidade que ainda
   está sendo usada por um cliente. O erro está registrado em
   execucao_completa.log (linha 168).

1) Criar tabela CT_RECEBER
----------------------------------------------------------------
CREATE TABLE CT_RECEBER(
    ID INT NOT NULL PRIMARY KEY,
    VENDA_ID INT NOT NULL,
    DATA_VENCIMENTO DATE,
    DATA_PAGAMENTO DATE,
    VALOR_PARCELA DECIMAL(10,2),
    JUROS DECIMAL(10,2),
    MULTA DECIMAL(10,2),
    VALOR_PAGO DECIMAL(10,2),
    NUMERO_PARCELA INT,
    TOTAL_PARCELAS INT,
    CONSTRAINT FK_CTRECEBER_VENDA FOREIGN KEY (VENDA_ID) REFERENCES VENDA(ID)
);
Executado com sucesso.
